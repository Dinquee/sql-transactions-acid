# 🔐 SQL-транзакции и ACID: объясняю на пальцах

Разберём одну из самых важных концепций в базах данных — **транзакции** и принципы **ACID**. Звучит страшно, но на деле всё просто. Давай с примерами.

---

## Что такое транзакция?

Транзакция — это набор SQL-операций, которые выполняются **как одно целое**. Либо всё выполнилось успешно, либо ничего не изменилось.

Классический пример: перевод денег между счетами.

```sql
BEGIN;

UPDATE accounts SET balance = balance - 1000 WHERE id = 1; -- списать у Димы
UPDATE accounts SET balance = balance + 1000 WHERE id = 2; -- начислить Васе

COMMIT;
```

Если между двумя `UPDATE` что-то пошло не так (отключился свет, упал сервер) — `ROLLBACK` откатит всё назад. Деньги не потеряются.

```sql
BEGIN;

UPDATE accounts SET balance = balance - 1000 WHERE id = 1;

-- вдруг ошибка! откатываем всё
ROLLBACK;
```

---

## ACID — что это за аббревиатура?

**ACID** — это четыре свойства, которые гарантирует надёжная база данных при работе с транзакциями:

| Буква | Слово | Смысл |
|-------|-------|-------|
| A | Atomicity (Атомарность) | Всё или ничего |
| C | Consistency (Согласованность) | БД остаётся в корректном состоянии |
| I | Isolation (Изолированность) | Транзакции не мешают друг другу |
| D | Durability (Долговечность) | После COMMIT данные не пропадут |

Разберём каждое подробнее.

---

## A — Атомарность (Atomicity)

> Транзакция — это атом. Её нельзя разделить пополам.

Если одна из операций внутри транзакции упала — вся транзакция откатывается. Никаких "списали деньги, но не зачислили".

```sql
BEGIN;

INSERT INTO orders (user_id, product_id, amount) VALUES (42, 7, 1);
UPDATE inventory SET stock = stock - 1 WHERE product_id = 7;

-- если UPDATE упал — INSERT тоже отменяется
COMMIT;
```

---

## C — Согласованность (Consistency)

> После транзакции данные должны оставаться логически правильными.

БД не позволит нарушить ограничения, которые ты сам задал — `FOREIGN KEY`, `NOT NULL`, `CHECK` и прочее.

```sql
-- создаём таблицу с ограничением: баланс не может быть отрицательным
CREATE TABLE accounts (
    id      SERIAL PRIMARY KEY,
    name    VARCHAR(100) NOT NULL,
    balance NUMERIC CHECK (balance >= 0)
);

-- эта транзакция упадёт, потому что баланс уйдёт в минус
BEGIN;
UPDATE accounts SET balance = balance - 9999 WHERE id = 1;
COMMIT; -- ❌ нарушение CHECK — транзакция откатится
```

---

## I — Изолированность (Isolation)

> Параллельные транзакции не должны влиять друг на друга.

Это самое хитрое свойство. Есть несколько уровней изоляции — от "почти ничего не защищает" до "полная изоляция":

| Уровень | Защищает от |
|---------|-------------|
| `READ UNCOMMITTED` | ничего |
| `READ COMMITTED` | грязного чтения |
| `REPEATABLE READ` | неповторяемого чтения |
| `SERIALIZABLE` | всего выше + фантомных строк |

```sql
-- Задаём уровень изоляции для сессии
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;

BEGIN;
SELECT balance FROM accounts WHERE id = 1; -- прочитали: 5000
-- другая транзакция в этот момент меняет баланс...
SELECT balance FROM accounts WHERE id = 1; -- всё равно видим: 5000 ✅
COMMIT;
```

На уровне `READ COMMITTED` второй `SELECT` мог бы вернуть уже новое значение — это называется **неповторяемое чтение**.

---

## D — Долговечность (Durability)

> Если транзакция завершена (`COMMIT`) — данные сохранены навсегда.

Даже если сервер упадёт сразу после `COMMIT`, при перезапуске база восстановит данные из журнала (`WAL` — Write-Ahead Log).

```sql
BEGIN;
INSERT INTO logs (event, created_at) VALUES ('user_login', NOW());
COMMIT; -- ✅ после этого данные уже на диске, даже если свет вырубится
```

## Быстрый пример: всё вместе

Симулируем покупку товара с полной защитой:

```sql
BEGIN;

-- проверяем наличие
SELECT stock FROM inventory WHERE product_id = 10 FOR UPDATE;
-- FOR UPDATE блокирует строку, чтобы другая транзакция не изменила её параллельно

-- списываем деньги
UPDATE accounts
SET balance = balance - 500
WHERE user_id = 42 AND balance >= 500; -- проверяем, что денег хватит

-- если ни одна строка не обновилась — денег не хватило, откатываем
-- (логика проверки на уровне приложения)

-- уменьшаем склад
UPDATE inventory SET stock = stock - 1 WHERE product_id = 10;

-- создаём заказ
INSERT INTO orders (user_id, product_id, total) VALUES (42, 10, 500);

COMMIT;
```

Если что-то пошло не так на любом шаге — `ROLLBACK`, и ни деньги, ни товар не тронуты.

---

## Итог

- **Транзакция** — группа операций, которая выполняется атомарно.
- **ACID** — набор гарантий, который делает работу с БД надёжной.
- `BEGIN` / `COMMIT` / `ROLLBACK` — твои главные инструменты.
- Уровни изоляции — тонкая настройка под конкретные задачи.

Транзакции используют все — от интернет-магазинов до банков. Понимание ACID помогает проектировать системы, которые не теряют данные и не ломаются под нагрузкой.
